# 同学上手指南（WorkBuddy 协作版）

> 目标：你那边打开 WorkBuddy，一条命令拉下最新代码，改完推回来，双方始终同一条基线。
> 全程不需要你记 git 原理，照下面抄命令就行。

---

## 0. 仓库与分支

```
https://github.com/qianxingzhigui/ai-learning-assistant2
```

| 分支 | 用途 | 你怎么用 |
| --- | --- | --- |
| `develop` | **日常开发主干**，所有改动都落这里 | 只在这个分支上干活 |
| `master` | 发布快照，内容跟随 `develop` | 不用管，`git clone` 默认就拿到它 |

> 2026-11-01 起 `master` 已快进到与 `develop` 同一提交，所以**直接 clone 拿到的就是最新代码**，
> 含历史学科改造、错题闭环、Gemini AI 接入。

## 1. 第一次：把仓库拉下来

先装好 Node 18+ 和 Python 3.10+（WorkBuddy 自带的 Python 也行）。

```bash
git clone https://github.com/qianxingzhigui/ai-learning-assistant2.git
cd ai-learning-assistant2
```

装依赖：

```bash
# 后端
cd backend
python -m pip install -r requirements.txt
cd ..

# 前端
cd frontend
npm install
cd ..
```

可选（想要 AI 能力才做）：

```bash
# Windows
copy backend\.env.example backend\.env
# macOS / Linux
cp backend/.env.example backend/.env
```

然后编辑 `backend/.env`，填自己那份 Key（**不要问别人要 Key，自己去申请**）：

| 平台 | 免费情况 | 要不要代理 |
| --- | --- | --- |
| 阶跃星辰 StepFun | 有活动额度，国内直连 | 不用（用 `https://api.stepfun.com/v1`，别用 `/step_plan/v1`） |
| 智谱 GLM-4-Flash | 永久免费 | 不用，国内直连 |
| Google Gemini | 新项目免费档已被停用 | **要**，且需绑卡，不建议 |

不填也能跑：AI 功能自动降级为本地规则引擎（资料检索 + 抽取式总结 + 统计分析）。

## 2. 启动

```bash
# 终端 A：后端（8000 端口）
cd backend
python -m uvicorn app.main:app --reload --port 8000

# 终端 B：前端（5173 端口，自动代理到 8000）
cd frontend
```

浏览器打开 <http://127.0.0.1:5173>，用演示账号 `demo` / `demo123` 登录即可看到完整数据。

## 3. 日常节奏（唯一需要记住的四步）

```bash
# ① 开工前：拉最新，别在旧基线上改
git checkout develop
git pull --no-rebase

# ② 干活……（可以让 WorkBuddy 直接改）

# ③ 提交前：跑测试，全绿再提交
cd backend && python -m pytest -q && cd ..

# ④ 提交 + 推送
git add -A
git commit -m "feat: 一句话说清改了什么"
git push origin develop
```

一条命令版（脚本会自己 pull 并告诉你基线是否最新）：

```bash
python scripts/board_report.py --me 你的名字 --pull
```

退出码：`0` 正常 / `1` 有阻塞任务 / `2` 代码不是最新。

## 4. 用 WorkBuddy 干活时的固定说法

WorkBuddy 不会自己知道协作规矩，开工前把这几句发给它（或写进 `.workbuddy/memory/MEMORY.md`）：

- **"先 `git pull --no-rebase` 再动手，别在旧基线上改。"**
- **"改完跑 `python -m pytest -q`，全绿再提交；红了先修，不要 `--no-verify` 跳过。"**
- **"远端有分歧用 `git merge`，不要用 `git rebase`。"**
- **"新增接口要同步改 `backend/tests/test_contract.py` 的 `CONTRACT_MANIFEST` 和末尾数量断言。"**
- **"新增业务表必须有 `uuid` 列，并同时加进 `main.py` 的 `USER_TABLES` 与 `sync.py` 的 `CHAIN`。"**

这五条是这个仓库的硬约束，违反任何一条都会让 CI 或契约测试变红。

## 5. 绝对不要提交的东西

仓库 `.gitignore` 已经挡住大部分，但别用 `git add -f` 绕过：

| 不要提交 | 原因 |
| --- | --- |
| `backend/.env`、任何 `.env` | 里面有别人或自己的 API Key |
| `data/*.db`、`release/data/*` | 本地学习数据，提交了会互相覆盖 |
| `data/token.key` | 登录令牌签名密钥，每台机器各自生成 |
| `node_modules/`、`frontend/dist/`、`backend/frontend_dist/` | 构建产物，体积大且能重建 |
| `release/`、`build/`、`*.zip` | 打包产物，走网盘分发 |

## 6. 冲突了怎么办

```bash
git pull --no-rebase
# 冲突会列出具体文件
git status
```

处理原则：

1. **同一个文件的冲突，谁后推谁解**，解完 `git add <文件>` 再 `git commit`。
2. 拿不准就把冲突文件贴给 WorkBuddy：「解释这两边的差异，给出合并方案，不要直接覆盖对方的改动」。
3. 千万别用 `git checkout --ours .` 一把梭，会把对方刚写的功能删掉。

**不要用 `git rebase`**：本机环境里 rebase 容易卡在中间态（HEAD detached、文件看起来被删），
用 `merge` 出问题随时 `git merge --abort` 就能退回。

## 7. 常见报错

| 现象 | 原因与处理 |
| --- | --- |
| `Authentication failed` / `could not read Username` | 凭据过期。用 GitHub 用户名 + Personal Access Token 当密码；或让 WorkBuddy 用 `gh auth login` 配一次 |
| `Failed to connect over proxy` | 全局 git 配了 `http.proxy=127.0.0.1:7897` 但代理没开。开代理，或临时 `git -c http.proxy= -c https.proxy= pull` |
| `remote-https is not a git command` | 用的是 PortableGit（当前环境常见）。设 `GIT_EXEC_PATH=<PortableGit>\mingw64\bin`，PATH 只放 `cmd` |
| 端口被占用 | 后端换 `--port 8001`；前端 Vite 会自动顺延 |
| pytest 用例名显示乱码 | Windows 控制台编码问题，不影响结果，看最后的 `N passed` 即可 |
| `no column named era` 之类 | 本地库是旧结构。删掉 `data/app.db` 重启，或跑 `python scripts/seed_history.py` 重建 |

## 8. 命令速查

| 想做什么 | 命令 |
| --- | --- |
| 拉最新 | `git pull --no-rebase origin develop` |
| 看自己改了什么 | `git status` / `git diff` |
| 跑测试 | `cd backend && python -m pytest -q` |
| 只跑接口契约 | `python -m pytest tests/test_contract.py -q` |
| 看我的任务 | `python scripts/board_report.py --me 你的名字` |
| 重建演示数据 | `python scripts/seed_history.py --clear` + `python scripts/seed_history_quiz.py` |
| 打包 exe | `python scripts/build_portable.py` |
