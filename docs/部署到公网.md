# 部署到公网：让手机/平板在任何网络下学习

> 前提先说清楚：**微信小程序不能连你电脑上的本地服务**——小程序要求 HTTPS + 备案域名。
> 所以「任何网络都能用」只有两条路：把家里电脑变成服务器（隧道方案），或把后端搬上云（正式方案）。

## 方案对比

| | A. 内网穿透（家里电脑当服务器） | B. 云服务器部署（推荐长期用） |
|---|---|---|
| 费用 | 0 ~ 域名 ¥10/年 | 服务器 ¥60~100/月（学生机约 ¥10/月）+ 域名 + 备案 |
| 电脑要求 | 学习时电脑必须开机联网 | 无要求，7×24 |
| 上手时间 | 10 分钟 | 半天（备案 1~4 周另计） |
| 适合 | 宿舍/家里自己用、答辩演示 | 全班/多人长期使用、后续接小程序 |

---

## 第 0 步（两个方案通用）：让服务监听外网

本程序默认只监听 `127.0.0.1`（安全默认值）。对外提供服务前：

- 便携版：命令行启动 `AILearningAssistant.exe --lan`（或先 `set APP_HOST=0.0.0.0` 再运行）
- 源码/容器：`APP_HOST=0.0.0.0`（Docker 镜像已默认）

⚠️ **公网部署的安全清单**：
1. **不要带内置 AI key**：用 `python scripts/build_portable.py --no-embed-key` 的思路，
   容器部署时在 docker-compose 里已设 `AI_DISABLE_BUILTIN=1`，让每个用户自己配 key。
   内置 key 一旦泄漏到公网，额度会被陌生人刷光。
2. 数据库在 `data/app.db`（SQLite 单文件），定期拷贝备份即可。
3. 全站已有账号体系（注册/登录/令牌），多用户隔离是按 `user_id` 做的，可以放心开放注册；
   不想开放就把登录页前的注册入口在 nginx/caddy 层挡掉（可选）。

## 方案 A：内网穿透（最快见效）

### A1. Cloudflare TryCloudflare（免费、零配置、临时域名）

```bash
# 先本机以局域网模式启动
AILearningAssistant.exe --lan
# 再起隧道（需要能访问外网）
cloudflared tunnel --url http://127.0.0.1:8000
```

控制台会打印一个 `https://xxx-yyy.trycloudflare.com` 的临时地址，手机直接用浏览器打开即可。
**注意**：临时地址每次重启都会变，且 Speed 有限，适合演示、不适合长期。

### A2. Cloudflare Tunnel + 自己的域名（稳定、免费）

1. 买个域名（任意 registrar，约 ¥10/年），把 NS 托管到 Cloudflare（免费计划）
2. `cloudflared tunnel login` → `cloudflared tunnel create ss-helper`
3. 配置 `~/.cloudflared/config.yml`：

```yaml
tunnel: ss-helper
credentials-file: C:\Users\你\.cloudflared\<tunnel-id>.json
ingress:
  - hostname: ss.你的域名.com
    service: http://127.0.0.1:8000
  - service: http_status:404
```

4. `cloudflared tunnel route dns ss-helper ss.你的域名.com` → `cloudflared tunnel run ss-helper`
5. 开机自启：`cloudflared service install`

之后手机访问 `https://ss.你的域名.com`，HTTPS 自动配好。**电脑关机服务就断**，这是该方案的天花板。

## 方案 B：云服务器部署（7×24）

### B1. 准备

1. 买一台云服务器（阿里云/腾讯云轻量 2C2G 即可，学生机有优惠）
2. 买域名并 **ICP 备案**（国内服务器必须；走云厂商的备案流程，1~4 周）
3. 服务器装 Docker（`curl -fsSL https://get.docker.com | bash`）

### B2. 部署

```bash
git clone https://github.com/qianxingzhigui/ai-learning-assistant2.git
cd ai-learning-assistant2
# 先在本机或服务器上构建前端
cd frontend && npm install && npm run build && cd ..
docker compose up -d --build
# 验证
curl http://127.0.0.1:8000/api/health
```

学习数据全部落在 `./data/`（宿主机目录），升级 = `git pull && docker compose up -d --build`，数据不丢。

### B3. HTTPS + 域名（Caddy，自动签证书）

服务器上另起一个 Caddy 容器，或直接用宿主机 Caddy，`Caddyfile` 两行搞定：

```
ss.你的域名.com {
    reverse_proxy 127.0.0.1:8000
}
```

（记得在云厂商安全组放行 80/443；备案通过前域名解析到国内服务器会被拦截。）

### B4. 日常维护

- 备份：`cp -r data data.bak.$(date +%F)`（或丢进对象存储）
- 升级：`git pull && docker compose up -d --build`
- 日志：`docker compose logs -f`

## 小程序（可选的最后一步）

上面 B 方案跑通后（HTTPS + 备案域名），小程序才有可能：
- 最省力：小程序里放一个 `web-view` 指向本站（要求该域名已备案 + 在小程序后台配置业务域名）
- 体验最好：重写一套小程序前端（WXML），复用现有 `/api/*` 接口

需要做的时候再说，接口层（登录、目录、史料、AI 对话）都是现成的。
