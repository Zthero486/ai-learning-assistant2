# 协作自动化：把「传话」这条人工链路删掉

> 目标：以后不需要任何人说「你去告诉他……」。改看板、push，剩下的由 GitHub 完成。

---

## 一、原来为什么会卡在人身上

```
你 → 口头/微信 → 他 → 手动 pull → 才可能看到
        ↑
     这一步会漏、会晚、会变形
```

手工传话的本质问题不是「说不清楚」，而是**必须有人主动发起**。只要发起动作依赖人，就会有一方在等。

现在的链路：

```
你改 docs/协作看板.md → git push
        ↓
GitHub Actions 自动执行 scripts/sync_tasks_to_issues.py
        ↓
给他建 Issue 并 @ 他 → GitHub 发邮件 + 手机推送
        ↓
他点开 Issue：任务全文已经在里面，不用 clone、不用 pull
        ↓
他改看板状态为 ✅ → push → Actions 自动关闭 Issue
```

**你这边唯一的动作是 push。** 没有第二步。

---

## 二、他需要做的（一次性，约 3 分钟）

### 第 1 步：订阅这个仓库

打开 https://github.com/qianxingzhigui/ai-learning-assistant2

右上角 **Watch** → **Custom** → 勾选：

- [x] Issues
- [x] Pull requests
- [x] Releases

> 只是一次。之后我每次派任务，他都会收到通知。
> 即使不订阅，Issue 正文里的 `@Zthero486` 也会触发一条 mention 通知——订阅只是多一层保险。

### 第 2 步：装手机端（可选但强烈建议）

GitHub 官方 App（iOS / Android）登录后，通知会直接推到手机。桌面邮件容易被淹没，手机推送不会。

### 第 3 步：在自己电脑的 WorkBuddy 里建一个每日自动化

这是最彻底的一层：**他那边主动去读仓库，不依赖任何通知**。

在 WorkBuddy 里新建自动化，周期设为每天早上 9:00，提示词直接粘贴下面这段（已写成自包含，未来的会话看不到今天的上下文）：

```
拉取 D:\WorkBuddyWorkSpace\SPB_Data\ai-learning-assistant2 的最新代码
（git checkout develop && git pull --ff-only），
然后运行 python scripts/board_report.py --me 黄吉航。

根据输出告诉我：
1. 我名下有哪些未完成任务，各自的任务卡是什么
2. 代码是否落后远端，如果落后先提醒我 pull
3. 相比较昨天，看板里新增或状态变化了哪些任务

如果 board_report.py 不存在，说明代码是旧的，先 fetch 再 pull，不要跳过。
汇报控制在 10 行以内，只说结论和下一步动作。
```

建完之后，他每天开电脑就已经知道该干什么，**完全不需要任何人开口**。

## 三、你这边怎么用（不变）

派活的流程还是三步，只是最后一步从「发微信」变成「push」：

```bash
# 1. 在 docs/协作看板.md 里加一行，或改某行状态
# 2. 如果有新任务，在 docs/tasks/ 下写任务卡
# 3. 提交并推送
git add -A
git commit -m "docs: 派发任务 T4"
git push origin develop
```

推送完成后 30 秒内，Actions 会跑完，他能收到通知。

**查看 Actions 是否成功**：
https://github.com/qianxingzhigui/ai-learning-assistant2/actions/workflows/task-dispatch.yml

## 四、自动化覆盖了什么、没覆盖什么

| 环节 | 是否自动 | 说明 |
| --- | --- | --- |
| 任务从看板变成他的通知 | ✅ 全自动 | push 即触发 |
| 任务卡全文送达 | ✅ 全自动 | 内嵌在 Issue 正文里 |
| 他完成后关闭任务 | ✅ 全自动 | 他改看板状态为 ✅ 即可 |
| 他订阅仓库 | ❌ 一次性手工 | 账户设置，只能本人在 GitHub 上点 |
| 他真的去看通知 | ❌ 依赖习惯 | 第 3 步的每日自动化可以兜底 |
| 他实际动手写代码 | ❌ 本来就不该自动 | — |

**没有一条自动化能强迫人干活。** 它能做的是：让「不知道要干什么」和「知道得太晚」这两个理由失效。

## 五、出问题时怎么查

**他没收到通知**

1. 打开 Actions 页面，看 `任务分派` 最近一次运行是不是绿色
2. 绿色但没通知 → 检查他的 Watch 设置和通知设置（GitHub 设置 → Notifications → 确认 Email 没被关掉）
3. 红色 → 点进去看日志，`sync_tasks_to_issues.py` 的输出会列出每个任务的处理结果

**Issue 建重复了**

不会。每个 Issue 正文里埋了 `<!-- task-sync:T1 -->` 标记，脚本按标记认领，重跑只更新不新建。如果真出现了重复，删掉多余的那个，下次 push 会自动收敛。

**他不想收到某一类通知**

不要改脚本。在 GitHub 通知设置里按 label 过滤即可，`任务分派` 是这批 Issue 的统一标签。

## 六、相关文件

| 文件 | 作用 |
| --- | --- |
| `docs/协作看板.md` | 唯一任务源，你改这里 |
| `docs/tasks/*.md` | 任务卡，Issue 正文会内嵌全文 |
| `scripts/sync_tasks_to_issues.py` | 看板 → Issue 的同步逻辑 |
| `.github/workflows/task-dispatch.yml` | 触发条件：push 到 develop 且改动涉及看板或任务卡 |
| `scripts/board_report.py` | 他那边一条命令查「我该干什么」 |
