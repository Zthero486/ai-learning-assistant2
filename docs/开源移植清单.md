# 开源移植清单

> 课设报告「参考与借鉴」一节可直接引用本文件。老师允许参考甚至搬用 GitHub 上的成品，
> 这里逐项记录**搬了什么、搬到哪、改了什么、为什么这么改、许可证怎么处理**，
> 以及**调研过但决定不搬的东西和理由**——选型对比本身就是工作量。

## 一、移植原则

1. **只搬算法与思路，不搬架构**。本项目是单文件 FastAPI + 裸 sqlite3 的课设规模，
   搬进来一整套框架（依赖注入、ORM、向量库）会把代码量翻倍却不增加功能。
2. **许可证合规**。只用 MIT / Apache-2.0 项目；复制代码的保留版权头，只借鉴设计的在文档注明。
3. **必须能降级**。新增第三方库若装不上或版本不兼容，功能退回原实现，软件不能因此起不来。
4. **数据不改结构**。新算法的状态尽量塞进"一列 JSON"，避免大改表、大改同步字段。

## 二、已移植

### 1. FSRS 间隔复习算法（错题本排期）

| 项 | 内容 |
|----|------|
| 上游 | [open-spaced-repetition/py-fsrs](https://github.com/open-spaced-repetition/py-fsrs) |
| 许可证 | MIT |
| 它是什么 | Anki 现役排期算法 FSRS-6（Free Spaced Repetition Scheduler）的 Python 实现，纯标准库、无网络调用 |
| 搬了什么 | `Card` / `Scheduler` / `Rating` 三个类的调用关系与状态序列化方式；不复制算法参数表，参数用库的默认值 |
| 落地位置 | `backend/app/srs.py`（适配层，约 230 行）<br>`wrong_book.srs`（卡片状态 JSON 一列）<br>`POST /api/practice/submit`（答题后重排）<br>`GET /api/review/due`（今日复习队列）<br>错题本「今日复习」视图 + 仪表盘提醒 |

**为什么值得搬**：原来的排期是 `REVIEW_INTERVALS = (1, 2, 4, 7, 15)` 的固定阶梯——
错第 3 次就一律 4 天后再复习，不管这道题是"忘了概念"还是"只是数字记混"。
FSRS 给每道题独立维护 **稳定度（stability）** 与 **难度（difficulty）**，答对/答错都按记忆曲线重算：

| 场景 | 旧（固定阶梯） | 新（FSRS） |
|------|----------------|------------|
| 第 1 次答错 | 1 天后 | 1 天后（难度记为高） |
| 隔天答对 | 仍然是 2 天后 | 2 天后，稳定度 2.3 |
| 再答对 | 4 天后 | **14 天后**（稳定度 13.8） |
| 第三次答对 | 7 天后 | **39 天后**（稳定度 39.2） |

**改动点（不是照抄）**：

- 学习步长由库默认的「1 分钟 / 10 分钟」改为「1 天」。这是每天打开一次的学习工具，
  不是一天刷几百张卡的背单词 App——默认参数会让答错的卡 1 分钟后就到期，学生根本不会回来。
- 关闭 `enable_fuzzing`（随机抖动）：单机演示场景下抖动只会让排期不好解释。
- 保留原来的「连对 2 次出库」规则，并新增「间隔 ≥ 21 天也算长期记住」——
  算法负责算时间，业务规则负责决定还要不要出现在错题本里。
- **缺包自动降级**：`import fsrs` 失败时全程走回旧的 1/2/4/7/15 阶梯，接口返回结构不变，
  前端无感（`backend/tests/test_srs.py::test_ladder_falls_back_without_fsrs` 守住这条）。

**同步兼容**：卡片状态存在 `wrong_book.srs`，已加入 `sync.py` 的导出/导入字段——
否则换台电脑复习计划就重置了。

### 2. 错题归因（AI 判断"错在哪一类"）

| 项 | 内容 |
|----|------|
| 上游 | GitHub 上的 AI 家教项目 `educational-tutor-ai`（错题归因 agent 设计） |
| 许可证 | Apache-2.0（**只借鉴设计，未复制代码**） |
| 搬了什么 | 错因分类法（概念混淆 / 时序错位 / 史论脱节 / 细节缺失 / 审题偏差 / 记忆不牢）+「先归因、再给改法」的对话流程 |
| 落地位置 | `ai_agent.ERROR_TYPES`（分类表）<br>`tag_wrong_error`（第 14 个 Agent 工具，写 `wrong_book.error_type`）<br>错题本「AI 错因诊断」按钮 → 跳转 AI 对话并自动发问 |

**为什么值得搬**：`wrong_book.error_type` 这一列建表时就有，但一直没人填——是个死字段。
归因工具让它活了：学生在 AI 对话里说一句"我为什么老错"，AI 会逐题判断错因、
调用工具把标签写进数据库，最后按错因归并成 2-3 条可执行的改法；
错题本上直接显示「错因：时序错位」。

**没搬的**：上游那套完整的 agent 编排框架（planner / memory / executor 分层），
与本项目单文件 `ai_agent.py` 的轻量实现冲突，性价比太低。

## 三、调研过但**不搬**的（选型对比，报告里可写"为什么不采用"）

| 候选 | 为什么不采用 |
|------|--------------|
| DeepTutor 的 Mastery Path（按掌握度解锁章节） | 需要完整知识图谱支撑，本项目 193 节里目前只有约 1/4 有知识点，解锁会大面积卡住。列为后续 |
| DeepTutor 的页面级引文（回答里每句锚到原文） | 体验好但要把答案句子对齐到原文 offset，工程成本高，当前用"检索片段 + 提示词要求不编造"替代 |
| 向量库 RAG（chroma / faiss + embedding 模型） | 便携包要控制在百 MB 内，不想捆 embedding 模型；继续用关键词打分检索（`ai_helper.search_chunks`） |

## 四、许可证合规做法

- **py-fsrs（MIT）**：`backend/app/srs.py` 文件头注明算法来源、仓库地址与 MIT 许可；
  未修改算法本体，只写适配层。
- **Apache-2.0 项目**：仅借鉴设计、未复制源码，因此不随附 NOTICE；
  若后续真要复制其源码，需在仓库根目录补 `NOTICE` 并保留文件头版权声明。
- 新增依赖记录在 `backend/requirements.txt`（`fsrs>=5.0`），并注明"装不上会自动降级"。
