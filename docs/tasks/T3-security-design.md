# T3 · 信息安全设计说明

**负责人**：黄吉航　**状态**：⏳ 待开始　**优先级**：高（课设评分独立考查项）　**对应评分点**：信息安全设计

## 交付物

在 `docs/` 下新建 **`信息安全设计说明.md`**，篇幅 **2000–3500 字**。

这份文档在答辩时会被追问「你们的安全考虑在哪」，所以**每一节都要有代码或配置里的真实依据**，不要写教科书式的空泛原则。

## 结构

```
# 信息安全设计说明

## 1. 威胁建模
   1.1 资产清单（用户学习数据、AI API Key、课程资料原文）
   1.2 攻击面分析（本地 HTTP 服务、浏览器↔后端、后端↔大模型 API）
   1.3 威胁列表（表格：威胁 / 影响 / 现有对策 / 残余风险）

## 2. 数据安全
   2.1 存储位置与隔离（data/ 目录、SQLite 单文件）
   2.2 数据库访问方式（参数化查询，防 SQL 注入）
   2.3 备份与清理（用户可自主删除，无云端上传）
   2.4 文件上传的风险控制（格式白名单、大小限制、文件名处理）

## 3. 密钥与凭据保护
   3.1 API Key 的三层存储（.env / 环境变量 / 界面配置）
   3.2 脱敏展示（mask_key，界面上只显示前4后4）
   3.3 日志与错误消息中不泄露 Key
   3.4 凭据不入库（.gitignore 覆盖 .env）

## 4. 通信安全
   4.1 本地服务只监听 127.0.0.1（不暴露到局域网）
   4.2 后端↔大模型 API 走 HTTPS
   4.3 明文 HTTP 的风险边界说明（为什么本地可接受）

## 5. 输入校验与异常处理
   5.1 Pydantic 请求模型校验
   5.2 路径穿越防护（文件上传/资料读取）
   5.3 统一异常处理，不向前端泄露堆栈

## 6. 依赖与供应链
   6.1 依赖清单与版本锁定（requirements.txt）
   6.2 CI 中执行代码风格与测试检查作为质量门
   6.3 已知未做的部分（诚实列出，如无认证、无速率限制）

## 7. 隐私合规
   7.1 数据不出本机（除显式调用大模型 API）
   7.2 调用大模型时发送了哪些内容（如实说明）
   7.3 用户如何完全删除自己的数据

## 8. 安全设计不足与改进方向
   表格：现状 / 风险等级 / 改进方案 / 是否在 v2 落地
```

## 必须核实的代码事实（照抄进文档，别猜）

写之前先在代码里确认下面每一项，确认后在文档里写明**文件路径 + 行号**：

| 查什么 | 去哪查 |
| --- | --- |
| 参数化查询（`?` 占位符） | `backend/app/main.py` 里所有 `execute(` 调用 |
| Key 脱敏函数 | `backend/app/ai_helper.py` → `mask_key()` |
| `.env` 是否被忽略 | 根目录 `.gitignore` |
| 上传格式白名单 | `backend/app/main.py` → `/api/materials/upload` 附近 |
| 服务监听地址 | `backend/launcher.py`、`scripts/start_backend.bat` |
| 请求模型校验 | `main.py` 里的 Pydantic class 定义 |

跑一遍这个命令把所有 SQL 抓出来看：

```bash
grep -n "execute(" backend/app/main.py
```
