# 打包与发布说明（便携绿色版）

> 对应课设评分点：部署执行 / 可运行软件交付 / 运行脚本

## 一、为什么需要打包

课设环节交付两种形态，各有用途：

| 形态 | 内容 | 用途 |
| --- | --- | --- |
| **源码态** | git 仓库 + 全部源码 + 测试 + CI | 老师评分、代码审阅、团队协作 |
| **发布态** | 单个 `AILearningAssistant.exe`（内嵌前端与 Python 运行时） | 自己使用、答辩现场演示、拷贝给同学 |

发布态解决了三个现实问题：对方电脑不需要安装 Python/Node、不需要联网装依赖、双击即可运行。

## 二、一键构建

```bash
python scripts/build_portable.py                 # 完整构建（含前端）
python scripts/build_portable.py --skip-frontend # 仅后端改动时复用已有前端产物
```

构建流程（脚本自动完成）：

```
npm run build               前端产物 frontend/dist
      ↓ 复制
backend/frontend_dist       随包分发的静态资源
      ↓ PyInstaller --onefile
release/AILearningAssistant.exe   单文件可执行程序
      ↓ 附上说明与配置模板
release/                    可直接拷贝分发的发布目录
```

产物结构：

```
release/
├── AILearningAssistant.exe   双击运行（约 40 MB，含 Python 运行时）
├── .env.example              可选：AI 配置模板（填 key 后改名为 .env）
├── 使用说明.txt              面向最终用户的操作说明
└── data/                     运行数据（首次启动自动创建）
    ├── app.db                学习数据
    └── uploads/              导入的原始文档
```

## 三、便携化设计

为做到"整个文件夹拷到别的电脑就能用"，做了四件事：

1. **数据目录随包**：`backend/app/apppaths.py` 在打包态把数据目录解析为 exe 同级目录 `data/`，开发态仍解析为项目根目录，两种形态共用一套代码。
2. **配置随包**：`.env` 从 exe 同级读取（开发态读 `backend/.env`），AI key 由使用者自行填入，不随包分发密钥。
3. **前端内嵌并同端口托管**：存在 `frontend_dist` 时由 FastAPI 挂载静态目录，浏览器访问 `http://127.0.0.1:8000` 即完整界面，无需 Node 与第二个端口。
4. **端口自动避让**：启动器从 8000 起探测可用端口（最多顺延到 8009），避免与开发环境或其他实例冲突；Windows 下不使用 `SO_REUSEADDR`，防止端口自检误判导致绑定失败。

## 四、分享给他人使用

### 4.1 生成分享包

```bash
python scripts/build_portable.py            # 构建并自动生成分享压缩包
python scripts/build_portable.py --zip-only # 不重新构建，仅重新打包
python scripts/build_portable.py --no-zip   # 只构建，不压缩
```

产物：项目根目录 `AI智能学习助手-v1.0-便携版.zip`（约 40 MB），解压后结构：

```
AI智能学习助手-v1.0/
├── AILearningAssistant.exe
├── 使用说明.txt
├── .env.example
└── data/                 （含演示数据，可直接演示；删掉即全新开始）
```

### 4.2 接收方要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 / 11（64 位） | 未做 macOS/Linux 版本 |
| Python / Node | **不需要安装** | 运行时已内嵌（含 `python313.dll`、`VCRUNTIME140.dll`） |
| VC++ 运行库 | **不需要安装** | 已随包携带 `VCRUNTIME140.dll` / `VCRUNTIME140_1.dll` |
| 浏览器 | 任意现代浏览器 | Edge / Chrome 等，不支持 IE |
| 磁盘空间 | ≥ 200 MB | exe 40 MB + 解压临时空间 |
| 权限 | 可写所在文件夹 | 数据写在 exe 同级 `data/` |
| 网络 | 不需要 | 纯本地单机运行，无账号、无联网上传 |

### 4.3 传输方式建议

- **推荐**：直接把 zip 放网盘（百度网盘/夸克/蓝奏等）或 U 盘；微信群/QQ 传 zip 通常可以，但部分企业微信/邮件网关会拦截含 exe 的压缩包。
- **不建议**：只发单个 exe（能跑，但接收方拿不到使用说明与 AI 配置模板）。
- 每个同学解压后各自独立，数据互不影响。

### 4.4 接收方可能遇到的拦截

未签名的 exe 首次运行可能被拦截，告知同学按下面处理即可：

1. **Windows SmartScreen**："Windows 已保护你的电脑" → 点"更多信息" → "仍要运行"。
2. **Windows Defender / 360 / 火绒**：提示"未知发布者/木马风险" → 选择"允许运行"或把该文件夹加入信任列表（这是 PyInstaller 打包程序的常见误报，源码全部在仓库中可查证）。
3. 公司/学校电脑若启用了应用白名单策略，可能无法运行——这属于设备管理限制，只能换设备。

### 4.5 接收方如何配置 AI（免改文件）

发布版把 AI 配置做进了界面，接收方不需要编辑任何文件：

1. 「AI 助手」页 → 点 **「配置 API Key」**
2. 「平台预设」选 **智谱 GLM（推荐，永久免费）**，`接口地址`/`模型名` 自动带出
3. 粘贴从 `open.bigmodel.cn` 控制台复制的 Key → **保存并生效**
4. 点 **「检测 AI 连接」**：显示绿色"连接成功"即完成；失败会给出具体原因
   （401 Key 无效 / 402 余额不足 / 404 地址或模型名错 / 429 触发限流 / 网络不通）

实现要点：`POST /api/config/ai` 会写回 exe 同级的 `.env` 并同时更新运行时环境变量，
因此 **无需重启程序**；读取接口 `GET /api/config/ai` 返回的 Key 经过脱敏处理
（只显示前后各 4 位），不会完整回显到界面。

实测记录（打包版 exe，填入一个无效 Key）：

| 步骤 | 结果 |
| --- | --- |
| 配置前 `GET /api/config/ai` | `configured=false`，可列出 5 个平台预设 |
| 保存配置 | 返回"配置已保存并生效"，exe 同级生成 3 行 `.env` |
| 保存后 `/api/health` | `ai_available=true`，地址与模型正确（未重启） |
| 检测连接 | 返回 `HTTP 401：API key 无效或未激活`（确实打到了智谱服务器） |
| 分享包 | 已确认不含 `.env`，不会泄露任何 Key |

## 五、启动器行为

`backend/launcher.py`（打包入口）：

1. 选择可用端口 → 2. 启动本地服务 → 3. 轮询 `/api/health` 就绪后自动打开默认浏览器 → 4. 打印中文提示（服务地址、数据目录、退出方式）→ 5. 关闭控制台窗口即退出程序。

## 七、已知问题

- **杀毒软件误报**：PyInstaller 产物未签名，可能被 Windows Defender/360 拦截，加入信任即可。若需公开发布，可考虑代码签名或改为 `--onedir` 目录模式。
- **首次启动稍慢**：单文件模式需把运行时解压到临时目录，冷启动约 3~10 秒（本机实测约 1 秒），属正常现象。
- **体积**：40.7 MB 中大部分为 Python 运行时与依赖（FastAPI、pypdf、python-docx 等）。
