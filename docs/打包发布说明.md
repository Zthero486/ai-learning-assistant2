# 打包与发布说明（便携绿色版）

> 对应课设评分点：部署执行 / 可运行软件交付 / 运行脚本

## 一、为什么需要打包

课设环节交付两种形态，各有用途：

| 形态 | 内容 | 用途 |
| --- | --- | --- |
| **源码态** | git 仓库 + 全部源码 + 测试 + CI | 老师评分、代码审阅、团队协作 |
| **发布态** | 单个 `AILearningAssistant.exe`（内嵌前端与 Python 运行时） | 自己使用、答辩现场演示、拷贝给同学 |

发布态解决了三个现实问题：对方电脑不需要安装 Python/Node、不需要联网装依赖、双击即可运行。

## 二、一键构建

```bash
python scripts/build_portable.py                 # 完整构建（含前端）
python scripts/build_portable.py --skip-frontend # 仅后端改动时复用已有前端产物
```

构建流程（脚本自动完成）：

```
npm run build               前端产物 frontend/dist
      ↓ 复制
backend/frontend_dist       随包分发的静态资源
      ↓ PyInstaller --onefile
release/AILearningAssistant.exe   单文件可执行程序
      ↓ 附上说明与配置模板
release/                    可直接拷贝分发的发布目录
```

产物结构：

```
release/
├── AILearningAssistant.exe   双击运行（约 40 MB，含 Python 运行时）
├── .env.example              可选：AI 配置模板（填 key 后改名为 .env）
├── 使用说明.txt              面向最终用户的操作说明
└── data/                     运行数据（首次启动自动创建）
    ├── app.db                学习数据
    └── uploads/              导入的原始文档
```

## 三、便携化设计

为做到"整个文件夹拷到别的电脑就能用"，做了四件事：

1. **数据目录随包**：`backend/app/apppaths.py` 在打包态把数据目录解析为 exe 同级目录 `data/`，开发态仍解析为项目根目录，两种形态共用一套代码。
2. **配置随包**：`.env` 从 exe 同级读取（开发态读 `backend/.env`），AI key 由使用者自行填入，不随包分发密钥。
3. **前端内嵌并同端口托管**：存在 `frontend_dist` 时由 FastAPI 挂载静态目录，浏览器访问 `http://127.0.0.1:8000` 即完整界面，无需 Node 与第二个端口。
4. **端口自动避让**：启动器从 8000 起探测可用端口（最多顺延到 8009），避免与开发环境或其他实例冲突；Windows 下不使用 `SO_REUSEADDR`，防止端口自检误判导致绑定失败。

## 四、启动器行为

`backend/launcher.py`（打包入口）：

1. 选择可用端口 → 2. 启动本地服务 → 3. 轮询 `/api/health` 就绪后自动打开默认浏览器 → 4. 打印中文提示（服务地址、数据目录、退出方式）→ 5. 关闭控制台窗口即退出程序。

## 六、已知问题

- **杀毒软件误报**：PyInstaller 产物未签名，可能被 Windows Defender/360 拦截，加入信任即可。若需公开发布，可考虑代码签名或改为 `--onedir` 目录模式。
- **首次启动稍慢**：单文件模式需把运行时解压到临时目录，冷启动约 3~10 秒（本机实测约 1 秒），属正常现象。
- **体积**：40.7 MB 中大部分为 Python 运行时与依赖（FastAPI、pypdf、python-docx 等）。
