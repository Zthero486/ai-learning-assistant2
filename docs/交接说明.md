## 一、这个项目是什么

《基于人工智能的智能学习助手软件》——软件工程课程设计（期末课设）。两人小组作业。

**它不是"调用大模型聊天"的玩具**，而是一个把 AI 嵌进学习流程的完整软件：把"课程资料 → 知识点 → 学习任务 → 练习 → 错题 → 学习记录"串成闭环，AI 作为其中的分析与生成模块（而非独立聊天窗）。

原始需求见 `docs/需求/开题报告.pdf`（提取版 `开题报告.txt`）。

**老师评分关注点**（决定了什么活优先干）：

| 类别 | 要求 |
| --- | --- |
| git 规范 | Conventional Commits、单一职责提交、分支/PR/issue、`.gitignore`、LICENSE、格式化工具、前后端解耦、部署与一键运行脚本 |
| 文档 | 用户手册、**重构前后 UML 对比 + 量化收益**、测试用例、演示视频、信息安全设计说明 |
| 团队 | 工作量度量方法（如代码量）、绩效分配方式及原因、两人都要有可见产出（代码 + 文档/测试 + issue/PR） |

## 四、环境搭建与运行

### 4.1 开发态（改代码用）

需要：Python 3.10+、Node.js 18+。

```bash
# 后端
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000     # 接口文档 http://127.0.0.1:8000/docs

# 前端（另开一个终端）
cd frontend
npm install
npm run dev                      # http://localhost:5173
```

Windows 下也可直接双击 `scripts\start_all.bat`（首次会自动建 venv 并装依赖）。

### 4.2 提交前必须做

```bash
cd backend
black --line-length 100 app tests && isort --profile black app tests
python -m pytest -q              # 必须全绿
cd ../frontend && npm run build  # 必须构建成功
```

### 4.3 打包便携版（给同学 / 答辩现场）

```bash
python scripts/build_portable.py              # 完整构建（含前端）
python scripts/build_portable.py --zip-only   # 只重新生成分享 zip
python scripts/build_portable.py --no-zip     # 只构建 exe
```

产物：`release/AILearningAssistant.exe` + 项目根 `AI智能学习助手-v1.0-便携版.zip`。

### 4.4 灌演示数据（录演示视频前）

```bash
python scripts/seed_demo.py --force
```

写入两门课程、3 份资料、7 个知识点、15 道题、38 条练习记录、11 道错题、5 个任务，
正确率有意分布在 25%~86% 之间，用于展示薄弱点判定。

## 五、已知坑与注意事项（都是真实踩过的）

| 问题 | 说明与对策 |
| --- | --- |
| **测试不得访问真实 AI** | `client` fixture 会清空 AI Key 保证走规则引擎；新增测试沿用该 fixture，否则会真的调用外部 API |
| **配置接口会改进程环境变量** | `POST /api/config/ai` 同时写 `.env` 和 `os.environ`（为了免重启生效）。相关测试必须在 fixture teardown 里清理 `AI_API_KEY/AI_BASE_URL/AI_MODEL` |
| **Windows 端口探测不能用 `SO_REUSEADDR`** | 它会让已占用端口被"抢绑"成功，导致自检误判后绑定失败。`launcher.py` 用 connect 探测 + 默认绑定语义，改这里要小心 |
| **`.env` 不能有 BOM** | 用 PowerShell `Set-Content` 写会带 BOM，导致首行 key 名解析失败。写配置文件一律用 Python `encoding='utf-8'` |
| **两次 Windows 编码坑** | 中文路径/内容读写统一显式指定 `encoding='utf-8'`；`.bat` 如需中文显示应存为 GBK |
| **批量删除会中断脚本** | 本机沙箱对递归删除敏感，`shutil.rmtree` 大目录后后续语句可能不执行（删除本身生效）。清大目录建议先重命名归拢再由人工清理 |
| **打包后的前端资源** | 打包时前端产物被复制到 `backend/frontend_dist/` 并内嵌进 exe；**改了前端必须重新打包**才会反映到 exe |
| **首次启动慢** | PyInstaller 单文件需解压运行时，冷启动约 3~12 秒，属正常 |
| **未做用户隔离** | 当前是单机单用户设计，没有登录/权限体系；无密钥、无联网上传 |

## 七、怎么把项目交给别人继续（同步方式）

### 方式一：Git 仓库（推荐，也是课设要交的东西）

```bash
# 在 GitHub / Gitee 新建空仓库后（由韦俊鑫操作）
git remote add origin <仓库地址>
git push -u origin master
git push origin develop
```

同学那边：

```bash
git clone <仓库地址>
cd ai-learning-assistant
git checkout develop
```

之后两人各自开分支开发、互发 PR，git 记录天然成为"协作痕迹"证据。

### 方式二：直接拷贝文件夹

把整个 `ai-learning-assistant` 文件夹（含 `.git`）压缩发过去，对方解压后用 WorkBuddy/CodeBuddy 打开这个文件夹作为工作空间即可。**注意**：`release/`、`build/`、`node_modules/`、`AI智能学习助手-*.zip` 体积大且可重建，传输前可以删掉，收到后按第四节重新构建。

### 关于"把对话本身同步过去"

- WorkBuddy 的「**分享任务**」按钮生成的是**公开只读链接**，对方能看到讨论过程，但不能在他的账号里继续这段对话。
- 想在同学那边接着干，正确方式是：他打开这个项目文件夹作为工作空间 → 新建任务 → 让 AI 读 `docs/交接说明.md`（本文）、`docs/项目开发日志.md` 与 `git log`，上下文就接上了。
- 也可直接把「分享任务」链接贴给他那边 AI 作为背景参考。

## 八、边界与约定

- **不要提交**：`release/`、`build/`、`node_modules/`、`data/`（数据库与上传文件）、`.env`（密钥）、分享 zip（已在 `.gitignore` 中）
- **不要删**：`docs/项目开发日志.md`、`git` 历史——它们是工作量与协作证据
- **改代码前**：先 `pytest` 确认基线绿；改完再跑一次
- **提交风格**：Conventional Commits（`feat/fix/docs/refactor/test/chore`），一次提交只做一件事，中文描述
- **密钥安全**：任何 Key 只写进 `.env`，绝不硬编码进代码或文档
