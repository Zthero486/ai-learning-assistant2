# 协作看板

> **这是两人之间唯一的任务交接渠道。** 所有"要对方做什么"都写在这里，不靠口头转述。
> 任务状态只改「状态」列，改完提交即可。

---

## 通知是自动的，不用等人开口

改完这个文件推送，GitHub 会**自动给对方建 Issue 并 @ 他**，他手机和邮箱会收到推送，点开就是任务全文（任务卡已经内嵌在 Issue 正文里，不用 pull 也能读）。

原理与排查见 [`协作自动化.md`](协作自动化.md)。

| 通道 | 触发方式 | 你需要做什么 |
| --- | --- | --- |
| GitHub Issue 通知 | 我改看板后 push | 无 |
| 一条命令查自己的活 | `python scripts/board_report.py --me 黄吉航` | 无 |
| 每日自动汇报 | 他那侧的 WorkBuddy 定时任务 | 建一次（见 `协作自动化.md` 第二节） |

## 怎么用（30 秒读完）

| 角色 | 操作 |
| --- | --- |
| **查任务** | 看下面的「待办」表，找你名字下面 `⏳ 待开始` / `🔄 进行中` 的行 |
| **看细节** | 每行有「任务卡」链接，点进去是完整步骤（命令、验收标准、注意事项） |
| **领任务** | 把状态改成 `🔄 进行中`，单独提交一次（`docs: 领取任务 xxx`） |
| **做完了** | 状态改 `✅ 已完成`，并在「交付说明」写清改了哪些文件、PR 链接 |
| **有阻塞** | 状态改 `🚫 阻塞`，在「备注」写清卡在哪，别硬等 |

**开工前跑这一条，它会告诉你「基线是不是最新 + 我该干什么」：**

```bash
python scripts/board_report.py --me 黄吉航 --pull
```

不加 `--me` 就列出全部人的任务。退出码：`0` 正常，`1` 有阻塞，`2` 代码不是最新。

**手工同步也可以用两条 git 命令：**

```bash
git checkout develop
git pull
```

**拉完确认一下，别在旧基线上干活：**

```bash
git log --oneline -1
```

应当显示 `7f2191d merge: 将 v2 重构准备阶段成果合入 develop` 或更新的提交。
如果显示 `707b74a`，说明拉的是旧 develop —— 那样你手上既没有本看板，也没有 `docs/tasks/T1~T3` 任务卡和 33 项契约测试，照着旧文档干活会白做。

> 本仓库自 2026-10-23 起，`develop` 已包含 v2 准备阶段全部成果（26 接口契约快照、练习页崩溃修复、刷新 404 修复）。`refactor-v2` 与 `develop` 当前内容一致，日常开工一律用 `develop`。
