# 信息安全设计说明

> 本文说明系统在账号安全、传输与接口安全、数据安全、AI 侧安全四个层面的设计，
> 以及已知风险与缓解。实现代码均可按文中文件路径定位复核。

---

## 1. 账号安全

### 1.1 口令存储：PBKDF2-HMAC-SHA256（`backend/app/auth.py`）

- 口令**从不明文落库**：`hashlib.pbkdf2_hmac("sha256", password, salt, 200_000)`，
  迭代 20 万次，盐为每用户随机的 16 字节 hex（`secrets.token_hex`）；
- 校验使用 `hmac.compare_digest`（常数时间比较），防时序侧信道；
- 零第三方依赖，算法为 NIST 推荐的口令哈希方案。

### 1.2 令牌：HMAC 签名 + 独立密钥文件

- 登录成功签发 `payload.hmac_sig` 形式的令牌（`make_token`），载荷为
  `user_id.过期时间`，防篡改、可过期；
- 签名密钥是 **32 字节 CSPRNG 随机数**（`secrets.token_bytes(32)`），存放在
  `data/token.key`（不在数据库、不入 git 仓库，`.gitignore` 明确排除）；
- 校验同样用 `compare_digest`；令牌过期或签名不符一律 401。
- 所有业务接口以 `Depends(require_auth)` 统一鉴权，未登录无法访问任何数据接口。

## 2. 接口与传输安全

| 措施 | 实现 |
| --- | --- |
| SQL 注入防护 | 全部业务查询使用**参数化 SQL**（`?` 占位符），动态表名仅来自服务端白名单常量（`USER_TABLES`），用户输入永远不拼接进 SQL |
| CORS 白名单 | 仅允许开发前端 `localhost:5173 / 127.0.0.1:5173`（`main.py` CORS_ORIGINS），生产由同源静态挂载提供服务 |
| 上传限制 | 单文件 ≤200MB（`MAX_UPLOAD_MB`），超限 400；按扩展名识别类型后以**服务端生成的文件名**落盘，用户提供的文件名只用于显示标题，杜绝路径拼接 |
| 外键约束 | 每个连接 `PRAGMA foreign_keys=ON`，防脏引用 |
| 数据归属隔离 | 所有查询/更新/删除都带 `AND user_id=?`，A 用户无法读写 B 用户的任何行（含 Agent 工具，见 §4） |

传输层按部署形态分级：本机使用回环地址；局域网为内网 HTTP；公网走 Cloudflare 隧道，
浏览器到 Cloudflare 边缘为 HTTPS（`部署到公网.md`）。自建域名可加反向代理 TLS。

## 3. 数据安全

- **密钥与配置分离**：AI API key、数据库口令等一律放 `.env`（`.gitignore` 排除），
  仓库只留 `.env.example`；分享版内置 key 由打包脚本注入 `backend/app/_builtin_key.py`
  并被 gitignore 排除，且提供 `--no-embed-key` 打包开关；
- **恢复默认即删 key**：`POST /api/config/ai` 传空 key 时仅删除 `.env` 中的 AI 行，
  不做任何落库操作；
- **备份**：数据库变更前自动落 `app.db.bak*`（gitignore 排除），zip 分发包内的
  `app.db.seed` 只在首次运行复制、**绝不覆盖**用户数据；
- **同步风险声明**：Git 式同步会把含密码哈希的账号 JSON 推送到同步仓库——
  文档明确建议使用**私有**仓库作同步枢纽（README 与用户手册均注明）；
- 已知取舍：SQLite 单文件便于课设级部署，磁盘层面依赖操作系统的文件权限。

## 4. AI Agent 侧安全（本项目的特色设计）

大模型获得写库/删库能力后，风险从"接口被滥用"变成"模型行为失控"。对策：

1. **权限分级**：24 个 Agent 工具分为 10 个只读 + 14 个写入/删除；删除类 7 个工具
   有专门提示词守则（`ai_agent.py` 规则 15）：删除前必须先只读确认目标存在、
   绝不凭记忆猜 id、删完逐条汇报；
2. **写入预算**（`WRITE_BUDGETS`）：单次对话知识点点 ≤6 批、题 ≤4 批、任务 ≤5 条、
   资料/事件各 ≤2——即使模型跑偏也无法刷库；读工具另有 `READ_BUDGETS` 防空转；
3. **数据归属强制**：Agent 工具内所有 SQL 同样强制 `user_id=?` 为当前登录用户，
   模型无法跨用户读写（有专门测试 `跨课程/跨用户边界` 覆盖）；
4. **行为评测护栏**：`scripts/agent_eval.py` 11 个场景（含"跨课程写入应拒绝"
   "模糊请求不乱写库"两个安全用例）自动判分，提示词或工具改动必须回归；
5. **异常必留痕**：所有兜底 `except` 必须记录异常（历史上静默吞异常导致降级
   不可见的教训已固化为约定与回归测试 `test_ai_paths.py`）。

## 5. 已知风险与后续计划

| 风险 | 现状 | 计划 |
| --- | --- | --- |
| 同步仓库若为 public 会泄露账号哈希 | 已文档声明 + 建议私有仓库 | 支持对同步 JSON 加密 |
| 局域网 HTTP 明文 | 课设部署形态可接受 | 可选自签证书/反向代理 TLS |
| 内置 key 可被逆向提取 | 文档明示只发给可信对象 | 服务端代理网关 |
| 令牌无刷新机制 | 30 天过期 | 短效 access + refresh 双令牌 |
